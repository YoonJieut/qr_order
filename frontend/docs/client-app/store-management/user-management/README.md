# 유저 정보 관리

## 메뉴명

`매장 관리 > 유저 관리(스태프 관리) > 유저 정보 관리`

현재 명세서에서는 `유저 관리(스태프 관리)`로 표기한다. 실제 메뉴명은 추후 스토리보드 또는 UI 문구 확정 단계에서 재검토한다.

## 기능명

스태프 계정 생성 및 메뉴 접근 권한 관리

## 기능 설명

client-admin이 매장 내부에서 사용할 스태프 계정을 생성, 수정, 비활성화하고, 각 스태프 계정별 메뉴 접근 권한을 부여하거나 삭제하는 기능이다.

## 접근 권한

- client-admin만 접근 가능하다.
- 스태프 계정은 접근할 수 없다.
- 해당 메뉴는 메뉴 접근 권한 설정 대상에서 제외한다.

## 화면 구성

- 한 화면에 두 개의 그리드를 배치한다.
- 왼쪽 그리드: 스태프 계정 목록
- 오른쪽 그리드: 선택한 스태프 계정의 메뉴 접근 권한 목록
- 왼쪽 그리드에서 스태프 계정을 선택하면 오른쪽 권한 목록을 갱신한다.
- 스태프 계정 추가는 모달 팝업에서 진행한다.

## 1차 권한 범위

- 메뉴 접근 권한 부여/삭제만 제공한다.
- 권한 프리셋은 제공하지 않는다.
- 버튼 단위 액션 권한은 1차 기능명세서에서 확정하지 않는다.
- 액션 권한은 추후 상세 스토리보드에서 화면별 버튼 활성화/비활성화 정책으로 정의한다.

## 유저 테이블 기준

| 항목 | 기준 |
| --- | --- |
| `sys_id` | 시스템 내부 식별자. 화면에는 노출하지 않는다. |
| `user_id` | 로그인 아이디. 스태프 계정 생성 시 입력한다. |
| `user_nm` | 사용자명. 스태프 계정 생성 시 입력한다. |
| `user_password` | 비밀번호. 생성/초기화 시 입력값을 서버에서 암호화 저장한다. |
| `password_fail_cnt` | 로그인 실패 횟수. 신규 생성 시 0으로 초기화한다. |
| `init_yn` | 비밀번호 초기화 여부. 신규 생성 시 `Y`로 저장한다. |
| `sys_plant_cd` | 사업장코드. client-admin의 사업장코드를 기준으로 자동 설정한다. |
| `plant_cd` | 소속 사업장코드. client-admin의 매장 코드로 자동 설정한다. |
| `insert_user_id` | 생성자 ID. 로그인한 client-admin의 `user_id`를 사용한다. |
| `insert_datetime` | 생성 일시. 서버에서 설정한다. |
| `modify_user_id` | 수정자 ID. 수정 시 로그인한 client-admin의 `user_id`를 사용한다. |
| `modify_datetime` | 수정 일시. 서버에서 설정한다. |

## 스태프 추가 모달 입력 항목

| 항목 | 필수 | 설명 |
| --- | ---: | --- |
| 아이디 | Y | 로그인에 사용할 `user_id` |
| 사용자명 | Y | 화면에 표시할 `user_nm` |
| 임시 비밀번호 | Y | 최초 로그인용 비밀번호 |
| 비밀번호 확인 | Y | 임시 비밀번호 재입력 |

## 신규 스태프 비밀번호 정책

- client-admin은 스태프 계정 생성 시 임시 비밀번호를 입력한다.
- 신규 생성된 스태프 계정의 `init_yn`은 `Y`로 저장한다.
- 스태프는 최초 로그인 시 임시 비밀번호로 인증한 뒤 비밀번호 변경 화면으로 이동한다.
- 비밀번호 변경 완료 전까지 client 앱 보호 화면에는 접근할 수 없다.
- 비밀번호 변경이 완료되면 `init_yn`은 `N`으로 변경된다.
