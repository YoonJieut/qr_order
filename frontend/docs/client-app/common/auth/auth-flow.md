# 인증 및 최초 비밀번호 변경

## 기능명

client 앱 로그인 및 최초 비밀번호 변경

## 기능 설명

client 앱 사용자가 로그인하고, 신규 생성 계정 또는 비밀번호 초기화 계정이 최초 로그인 시 비밀번호를 변경하도록 강제하는 공통 인증 흐름이다.

## 적용 대상

- client-admin
- 스태프 계정
- `init_yn = Y`인 계정은 역할과 관계없이 최초 비밀번호 변경 대상이다.
- 시스템 관리자(admin)가 client-admin을 초기 생성하거나 비밀번호를 초기화한 경우의 적용 방식은 스토리보드/API 단계에서 확정한다.
- 1차 MVP 권장안은 client-admin도 `init_yn = Y`이면 동일한 최초 비밀번호 변경 흐름을 적용하는 것이다.

## 기본 로그인 흐름

1. 사용자가 client 앱 로그인 화면에서 아이디와 비밀번호를 입력한다.
2. 서버 인증이 성공하면 사용자 정보와 `init_yn` 값을 확인한다.
3. `init_yn = N`이면 client 앱 인증 필요 화면에 진입한다.
4. `init_yn = Y`이면 비밀번호 변경 화면으로 이동한다.

## 최초 비밀번호 변경 흐름

- 신규 스태프 계정은 생성 시 `init_yn = Y`로 저장한다.
- `init_yn = Y`인 사용자는 임시 비밀번호로 로그인한 뒤 비밀번호 변경을 완료해야 한다.
- 비밀번호 변경 완료 전까지 메인 대시보드, 주문, 매장, 메뉴, 결제, 게시판 등 client 앱 인증 필요 화면에 접근할 수 없다.
- 비밀번호 변경이 성공하면 서버는 `init_yn`을 `N`으로 변경한다.
- 비밀번호 변경 완료 후 사용자는 client 앱 기본 진입 화면으로 이동한다.

## 비밀번호 변경 입력 항목

| 항목 | 필수 | 설명 |
| --- | ---: | --- |
| 새 비밀번호 | Y | 사용자가 앞으로 사용할 비밀번호 |
| 새 비밀번호 확인 | Y | 새 비밀번호 재입력 |

## 검증 정책

- 새 비밀번호와 새 비밀번호 확인 값은 일치해야 한다.
- 1차 MVP 비밀번호 규칙은 다음을 기준으로 한다.
  - 최소 8자
  - 영문, 숫자, 특수문자 조합 필수
  - 특수문자 최소 1개 포함
- 최초 비밀번호 변경 화면에서는 기존 비밀번호를 입력받지 않는다.
- 임시 비밀번호 만료와 비밀번호 재사용 금지는 1차 범위에서 제외한다.
- 비밀번호 복잡도 정책이 보안 정책 또는 API 명세에서 변경되면 해당 기준을 우선한다.

## 화면 상태 및 오류 표시 정책

| 상황 | 처리 |
| --- | --- |
| 아이디 미입력 | 로그인 화면 내 필드 오류 메시지를 표시한다. |
| 비밀번호 미입력 | 로그인 화면 내 필드 오류 메시지를 표시한다. |
| 로그인 실패 | 로그인 화면 내 오류 메시지를 표시한다. |
| 계정 잠금 | 로그인 화면에서 잠금 안내를 표시한다. |
| 새 비밀번호 미입력 | 비밀번호 변경 화면 내 필드 오류 메시지를 표시한다. |
| 비밀번호 확인 미입력 | 비밀번호 변경 화면 내 필드 오류 메시지를 표시한다. |
| 새 비밀번호와 확인 값 불일치 | 비밀번호 변경 화면 내 필드 오류 메시지를 표시한다. |
| 비밀번호 규칙 미충족 | 비밀번호 변경 화면 내 필드 오류 메시지를 표시한다. |
| 비밀번호 변경 요청 중 | 제출 버튼을 비활성화하고 중복 제출을 방지한다. |
| 비밀번호 변경 성공 | 완료 안내 후 client 앱 기본 진입 화면으로 이동한다. |
| 서버 오류 또는 네트워크 오류 | ErrorModal로 오류를 안내한다. |
| 세션 만료 또는 401 | 1차 MVP 권장안은 인증 만료 안내 후 client 로그인 화면으로 이동하는 것이다. |

## 인증 필요 화면 접근 정책

- 로그인하지 않은 사용자가 client 앱 인증 필요 화면에 접근하면 client 로그인 화면으로 이동한다.
- 로그인했지만 `init_yn = Y`인 사용자가 인증 필요 화면에 접근하면 비밀번호 변경 화면으로 이동한다.
- 메뉴 접근 권한이 없는 화면에 접근하면 접근 불가 안내 화면 또는 권한 없음 상태를 표시한다.
- 인증 필요 화면 URL에 직접 접근하거나 새로고침해도 위 정책을 동일하게 적용한다.
- `init_yn = Y` 상태에서 브라우저 뒤로가기로 인증 필요 화면에 접근하려 하면 비밀번호 변경 화면으로 다시 이동한다.
- 이미 로그인했고 `init_yn = N`인 사용자가 로그인 화면에 접근하면 client 앱 기본 진입 화면으로 이동한다.
- 비밀번호 변경 화면은 인증에 성공했고 `init_yn = Y`인 사용자만 접근할 수 있다.
- 비밀번호 변경 대상이 아닌 사용자가 비밀번호 변경 화면에 접근하면 client 앱 기본 진입 화면으로 이동한다.
- 상세 리다이렉트 타이밍, URL 유지 여부, 접근 불가 화면 문구는 스토리보드/API 단계에서 확정한다.

## 인증 오류 처리

| 상황 | 처리 |
| --- | --- |
| 로그인 API 실패 | 로그인 화면 내 오류 메시지를 표시한다. |
| 로그인 API 401 | 로그인 실패로 처리하고 로그인 화면 내 오류 메시지를 표시한다. |
| 인증 필요 API 401 | 1차 MVP 권장안은 인증 만료 안내 후 client 로그인 화면으로 이동하는 것이다. |
| 비밀번호 변경 API 401 | 1차 MVP 권장안은 인증 만료 안내 후 client 로그인 화면으로 이동하는 것이다. |
| 메뉴 접근 403 | 1차 MVP 권장안은 client 앱 내 접근 불가 안내 화면을 표시하는 것이다. |
| 액션 실행 중 403 | 권한 없음 오류를 안내한다. 버튼 단위 권한 정책은 스토리보드 단계에서 보완한다. |
- 401/403별 정확한 화면 문구, 모달 사용 여부, 재시도 동선은 스토리보드/API 단계에서 확정한다.

## 유저 정보 관리와의 관계

- client-admin이 스태프 계정을 생성하면 신규 계정의 `init_yn`은 `Y`로 저장한다.
- client-admin은 스태프가 최초 로그인에 사용할 임시 비밀번호를 설정한다.
- 임시 비밀번호 전달 방식은 스토리보드/API 단계에서 확정한다.
- 스태프는 최초 로그인 후 직접 새 비밀번호를 설정한다.
- 이 흐름은 스태프가 임시 비밀번호를 장기간 사용하는 것을 방지하기 위한 정책이다.
- 스태프 계정 생성 입력 항목과 계정 관리 정책은 [유저 정보 관리](../../store-management/user-management/user-management.md)를 따른다.
